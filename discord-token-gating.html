How to Token-Gate a Discord Server

8 min read · Collab.Land & Guild.xyz walkthrough

Token-gating Discord means members automatically receive a role — and access to private channels — when their wallet holds your token or NFT. It takes about 15 minutes with a no-code bot.

1. Plan your roles

Design roles before you touch a bot. A common structure:

  • Verified — any wallet connected (anti-bot baseline)
  • Holder — owns ≥1 NFT
  • Whale / Tier 2 — owns ≥5 or a rare trait
  • OG — held since a date, or a POAP from your first event

Model the logic with our Rule Builder.

2. Option A — Collab.Land

  1. Invite the Collab.Land bot to your server from its website and grant it the permissions it requests.
  2. Make sure the Collab.Land role sits above the roles it assigns in Server Settings → Roles.
  3. Open the Command Center and create a Token Granted Role (TGR): pick chain, token type, contract address, minimum balance, and role.
  4. Create a #verify channel visible to everyone; the bot posts a “Let's go!” verification button.
  5. Test with a holder wallet and a non-holder wallet.

Best for: Discord/Telegram-first projects, small communities (free tier covers up to 25 verified members).

3. Option B — Guild.xyz

  1. Create a Guild, connect your Discord server and add the Guild bot.
  2. Add roles with requirements (token, NFT, POAP, allowlist, GitHub, X, and more) with AND/OR logic.
  3. Map each Guild role to a Discord role.
  4. Share your guild page link; members join there and roles sync automatically.

Best for: multi-platform communities, points & leaderboards, and growing servers that prefer flat-tier pricing.

4. Configure channels

  • Deny @everyone “View Channel” on holder categories; allow the Holder role.
  • Keep a public #welcome, #verify and #faq so new people know how to get in.
  • Pin a warning: “We will never DM you a verify link.”

5. Security & anti-bot

  • Disable DMs from server members for new joiners where possible.
  • Add a humanity requirement (e.g. Gitcoin Passport) to high-value roles.
  • Only link to the bot's official domain. Never ask members to approve tokens.

Common mistakes

  • Bot role placed below the gated role — assignments silently fail.
  • Wrong chain selected for the contract.
  • No re-verification, so sellers keep access.
  • Gating everything — keep a public funnel for newcomers.
